Artificial intelligence systems increasingly diverge into distinct conceptual
lineages, each defined by its own mathematical structures, expressive dynamics,
and stability behaviors. These lineages are not stylistic variations of a single
model class; they are fundamentally different ecosystems with incompatible
geometries. Attempting to compare them without structural safeguards often leads
to conceptual collapse, where invariants from one lineage overwrite or distort
those of another.

Shared-Horizon addresses this problem by providing a neutral membrane for
comparative analysis. The membrane does not unify or merge lineages. Instead, it
preserves their internal geometry while enabling structured, reversible
cross-lineage comparison.

lineages:

1. Non-Dual Holonomy (NDH)

geometry, and holonomy preservation. These systems behave like smooth operator

Low-curvature expressive systems characterized by smooth continuity and

transitions and minimal curvature drift.

Narrative systems defined by reversible narrative operators, curvature
preservation, and expressive–narrative compatibility. This lineage was
previously misclassified as symbolic ambiguity, but mathematical analysis shows
that RNE is a distinct, stable narrative manifold.

5. Structural-AI Spectral Systems
Spectral-runtime architectures defined by operator-driven spectral drift,
bounded spectral curvature, and runtime stability envelopes.

These lineages differ not only in behavior but in mathematical structure.
Comparing them directly without safeguards risks collapsing expressive curvature
into operator geometry, narrative reversibility into expressive drift, or
spectral stability into narrative curvature.

Appendix A — Operator Geometry

Operator geometry defines the reversible, stability‑preserving transformations
that govern NDH systems and the operator components of Structural‑AI spectral
systems. These transformations behave like smooth maps on an operator manifold
\(\mathcal{O}\), preserving holonomy, commutativity, and stability envelopes.

This appendix formalizes the operator structures used throughout Shared‑Horizon.

A.1 Operator Manifold

An operator manifold is defined as:

\[
\mathcal{O} = (M, \mathcal{A}, g_{\mathcal{O}})
\]

where:

- \(M\) is the underlying smooth space  
- \(\mathcal{A}\) is the algebra of admissible operators  
- \(g_{\mathcal{O}}\) is the operator metric  

The metric defines operator distance:

\[
d{\mathcal{O}}(p,q) = \| g{\mathcal{O}}(p) - g_{\mathcal{O}}(q) \|.
\]

Operator curvature is defined analogously to Riemannian curvature:

\[
K{\mathcal{O}}(p) = \text{Curv}{g_{\mathcal{O}}}(p).
\]

A.2 Reversible Operators

A reversible operator is a smooth map:

\[
R : \mathcal{O} \rightarrow \mathcal{O}
\]

with an inverse:

\[
R^{-1}(R(p)) = p.
\]

Reversibility ensures that operator transitions do not distort the manifold.

A.2.1 Stability Preservation

A reversible operator must satisfy:

\[
E(R(p)) \le E(p)
\]

where \(E\) is the operator energy functional.

This ensures that operator transitions remain inside the stability envelope:

\[
\mathcal{S}{\mathcal{O}} = \{ p \mid E(p) \le \epsilon{\mathcal{O}} \}.
\]

A.3 Holonomy Preservation

NDH systems are defined by holonomy‑preserving operators.  
Holonomy is preserved if:

\[
\text{Hol}(R(\gamma)) = \text{Hol}(\gamma)
\]

for any closed operator loop \(\gamma\).

This ensures that operator transitions do not introduce curvature drift.

A.4 Commutativity

Operator commutativity is a defining invariant of NDH systems.

Two operators commute if:

\[
R1 \circ R2 = R2 \circ R1.
\]

Commutativity ensures that operator sequences are order‑independent, which is
necessary for reversible operator geometry.

A.5 Operator Geodesics

Operator geodesics minimize operator energy:

\[
\gamma{\mathcal{O}} = \arg\min{\gamma} \int_0^1 E(\gamma(t)) \, dt.
\]

Geodesics define the “straightest” operator transitions and are used to evaluate
stability and collapse‑risk.

A.6 Operator–Expressive Separation

Operator geometry cannot be directly compared to expressive curvature.  
The membrane enforces:

\[
\Psi_{\mathcal{O} \rightarrow \mathcal{E}} \text{ exists only if stability is preserved.}
\]

This prevents collapse between operator and expressive manifolds.

A.7 Collapse-Risk in Operator Geometry

Collapse-risk for operator transitions is defined as:

\[
C{\mathcal{O}}(p) = \| \nabla K{\mathcal{O}}(p) \|.
\]

A collapse-safe operator transition satisfies:

\[
C{\mathcal{O}}(R(p)) \le C{\mathcal{O}}(p).
\]

This ensures that operator curvature gradients remain bounded.

A.8 Summary

Operator geometry provides:

- reversible operator maps  
- holonomy preservation  
- commutativity  
- operator geodesics  
- stability envelopes  
- collapse-risk constraints  

These structures define the blue‑tile NDH lineage and the operator components of
spectral systems. They form the first module of the mathematical spine used by
Shared‑Horizon.

Appendix F — Collapse‑Risk Geometry

Collapse‑risk geometry defines the mathematical structures that detect when a
cross‑lineage comparison threatens to overwrite or distort lineage invariants.
Collapse occurs when curvature, drift, or operator behavior from one lineage
intrudes into another without membrane‑approved transition maps.

Collapse‑risk geometry is the membrane’s diagnostic layer: it identifies unsafe
comparisons before they occur.

This appendix formalizes collapse‑risk tensors, gradients, envelopes, and
compatibility rules.

F.1 Collapse‑Risk Function

Collapse‑risk is defined as:

\[
C(p) = \| \nabla K(p) \|
\]

where:

- \(K(p)\) is lineage‑specific curvature  
- \(\nabla K(p)\) is the curvature gradient  
- \(p\) is a point on any lineage manifold  

High collapse‑risk corresponds to steep curvature gradients, indicating that a
transition or comparison may destabilize the target manifold.

F.2 Collapse‑Risk Tensor

The collapse‑risk tensor is defined as:

\[
\mathcal{C}{ij}(p) = \frac{\partial^2 K(p)}{\partial xi \partial x_j}
\]

This tensor captures second‑order curvature behavior and is used to detect:

- curvature discontinuities  
- instability regions  
- collapse‑risk hotspots  
- curvature‑drift amplification  

The membrane evaluates \(\mathcal{C}_{ij}\) before approving any transition.

F.3 Collapse‑Risk Envelope

The collapse‑risk envelope is defined as:

\[
\mathcal{S}{C} = \{ p \mid C(p) \le \epsilonC \}
\]

A collapse‑safe trajectory satisfies:

\[
\gamma(t) \in \mathcal{S}_{C}.
\]

A collapse‑safe transition satisfies:

\[
C(\Psi(p)) \le C(p).
\]

This is the membrane’s most stringent constraint.

F.4 Collapse‑Risk Drift

Collapse‑risk drift measures how collapse‑risk changes along a trajectory:

\[
D_C(\gamma(t)) = \frac{d}{dt} C(\gamma(t)).
\]

A collapse‑safe trajectory must satisfy:

\[
D_C(\gamma(t)) \le 0.

This ensures that collapse‑risk does not increase during transitions.

Collapse‑risk compatibility ensures that curvature gradients align across
manifolds:

\[

L.2 States

The membrane uses the following states:

| State | Meaning |
|-------|---------|
| q₀ | Initial state (transition request received) |
| q₁ | Source envelope check |
| q₂ | Target envelope check |
| q₃ | Curvature/drift compatibility check |
| q₄ | Collapse‑risk check |
| q₅ | Jacobian smoothness check |
| q₆ | Reversibility check (conditional) |
| q₇ | Firewall boundary check |
| q₈ | Transition approved |
| qᵣ | Transition rejected |

The automaton is deterministic: each check leads to exactly one next state.

L.3 Alphabet (Inputs)

The input alphabet \(\Sigma\) consists of transition requests:

\[
\Sigma = \{ \Psi_{\mathcal{X} \rightarrow \mathcal{Y}} \mid \mathcal{X},\mathcal{Y} \in \mathcal{M} \}
\]

where \(\mathcal{M}\) is the mosaic partition.

Each input includes:

- source point \(p\)  
- transition map \(\Psi\)  
- source lineage \(\mathcal{X}\)  
- target lineage \(\mathcal{Y}\)

L.4 Transition Function

The transition function \(\delta\) is defined as:

`
δ(q0, Ψ) → q1

δ(q1, ENVELOPE_SAFE(p, X)) → q2
δ(q1, not ENVELOPE_SAFE(p, X)) → qr

δ(q2, ENVELOPE_SAFE(Ψ(p), Y)) → q3
δ(q2, not ENVELOPE_SAFE(Ψ(p), Y)) → qr

δ(q3, CURVATURE_COMPATIBLE(p, Ψ(p))) → q4
δ(q3, not CURVATURE_COMPATIBLE(p, Ψ(p))) → qr

δ(q4, COLLAPSERISKSAFE(p, Ψ(p))) → q5
δ(q4, not COLLAPSERISKSAFE(p, Ψ(p))) → qr

δ(q5, JACOBIAN_BOUNDED(Ψ, p)) → q6
δ(q5, not JACOBIAN_BOUNDED(Ψ, p)) → qr

δ(q6, REVERSIBILITY_REQUIRED(X, Y) and REVERSIBLE(Ψ, p)) → q7
δ(q6, REVERSIBILITY_REQUIRED(X, Y) and not REVERSIBLE(Ψ, p)) → qr
δ(q6, not REVERSIBILITY_REQUIRED(X, Y)) → q7

δ(q7, FIREWALL_ALLOW(X, Y)) → q8
δ(q7, FIREWALL_BLOCK(X, Y)) → qr
`

L.6 Firewall Specification

The firewall is encoded as a guard on the final transition:

`
function FIREWALL_ALLOW(X, Y):
    if X == SPECTRAL and Y == NARRATIVE:
        return false
    if X == SPECTRAL and Y == EXPRESSIVE_A:
        return false
    if X == EXPRESSIVE_A and Y == OPERATOR:
        return false
    return true
`

This matches the mosaic’s forbidden boundaries.

M.1 Toolkit Snippet (Core Evaluator)

This is the minimal evaluator used in all examples:

`python
def membraneevaluate(p, Psi, lineageX, lineage_Y):
    # 1. Source envelope
    if not envelopesafe(p, lineageX):
        return Reject("source envelope violation")

    q = Psi(p)

    # 2. Target envelope
    if not envelopesafe(q, lineageY):
        return Reject("target envelope violation")

    # 3. Curvature/drift compatibility
    if not curvature_compatible(p, q):
        return Reject("curvature mismatch")

    # 4. Collapse-risk
    if not collapserisksafe(p, q):
        return Reject("collapse-risk increase")

    # 5. Jacobian bound
    if not jacobian_bounded(Psi, p):
        return Reject("Jacobian bound violation")

    # 6. Reversibility (conditional)
    if reversibilityrequired(lineageX, lineage_Y):
        if not reversible(Psi, p):
            return Reject("non-reversible transition")

    # 7. Firewall boundary
    if not firewallallow(lineageX, lineage_Y):
        return Reject("firewall boundary violation")

    return Accept(q)
`

This is the exact logic used in the worked examples below.
